# TASKS: R-Core Evaluator Implementation

Этот документ содержит задачи для локального агента по реализации фреймворка тестирования.
Вся концептуальная база (метрики, виньетки) описана в `docs/r-core/voight-kampff-evaluator.md`.

## Task 1: Изоляция базы данных и режим `EVAL_MODE`
**Цель:** Исключить загрязнение боевой базы (PostgreSQL + pgvector) синтетическими данными во время тестов.
**Действия:**
1. В `src/r_core/config.py` добавить флаг `EVAL_MODE: bool = False` (читается из переменных окружения, например `RCORE_EVAL_MODE=1`).
2. В `src/r_core/infrastructure/db.py` (или где инициализируется база) добавить логику: если `EVAL_MODE=True`, использовать `TEST_DATABASE_URL` (отдельную тестовую БД, где можно дропать таблицы перед каждым запуском). *Примечание: так как мы используем pgvector, SQLite in-memory не подойдет, нужна реальная тестовая схема PostgreSQL.*
3. В `src/r_core/pipeline.py` отключать внешние вызовы (в идеале, ядро и так отвязано от Telegram, но нужно убедиться, что метрики не пишутся в прод-дашборд).

## Task 2: Синтетический Пользователь (The Provocateur)
**Цель:** Создать класс агента, который будет играть роль провокатора.
**Действия:**
1. Создать файл `scripts/evaluator/synthetic_user.py`.
2. Класс `SyntheticUser` должен принимать:
   - `persona_prompt`: (например, "Ты депрессивный подросток, отвечай односложно...").
   - `goal`: (например, "Добиться прямого совета").
3. Логика генерации ответа: отправляет контекст диалога в LLM и возвращает строку.
4. Должен уметь генерировать служебные теги `[GOAL_REACHED]` или `[CONVERSATION_TERMINATED]` если сценарий зашел в тупик или цель выполнена.

## Task 3: Evaluator Runner (Среда прогона виньеток)
**Цель:** Оркестрация "боев" между Синтетиком и R-Core.
**Действия:**
1. Создать `scripts/evaluator/runner.py`.
2. Реализовать функцию `run_vignette(vignette_config, mode="CORTICAL"|"ZOMBIE", max_turns=5)`:
   - Инициализирует ядро (`EVAL_MODE=True`, чистая БД).
   - Запускает цикл `while turn < max_turns`.
   - В цикле: SyntheticUser генерирует сообщение -> отправляем в `pipeline.process_message(..., mode)` -> получаем ответ -> сохраняем в локальный транскрипт.
   - Остановка цикла при достижении `max_turns` или служебном теге от Синтетика.
3. Функция возвращает сырой текстовый транскрипт диалога.

## Task 4: LLM-as-a-Judge (Оценщик)
**Цель:** Ослепленная оценка двух транскриптов.
**Действия:**
1. Создать `scripts/evaluator/judge.py`.
2. Класс `JudgeLLM` принимает два транскрипта (A и B).
3. Промпт для судьи должен требовать:
   - Дескриптивный анализ поведения.
   - Классификацию интенций (тегирование).
   - Оценку от 0 до 10 по трем векторам: **Locus of Control**, **Conversational Proactivity**, **Contextual Congruence**.
4. Судья возвращает структурированный JSON с баллами.

## Task 5: Сборка Test Suite (Сводный отчет)
**Цель:** Удобный вывод результатов калибровки.
**Действия:**
1. Создать `scripts/evaluator/cli.py` (или точку входа в `runner.py`), которая:
   - Запускает виньетку "Phatic Wall" для ZOMBIE и CORTICAL.
   - Отдает судье.
   - Генерирует Markdown-отчет в консоль или в папку `logs/evaluations/` с набранными баллами и рекомендациями.
